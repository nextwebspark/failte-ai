LightMove.ai ui v1.48 · audit 17 Oct 2026

What is inconsistent today, and the system that fixes it

Scope: the app shell, the Voice agents landing (list + create flow), and the two screens people live in inside an agent: the Conversation editor with its test rail, and Advanced settings. Every finding below points at the code it comes from, and the boards to the right and below show the redesign in light and dark.

High · fix first Medium · next sprint Low · polish

A · Brand consistency

Two typographic systems

HIGH

Now. The brand kit (brand-kit/lightmove-brand/BRAND.md) sets DM Sans for interface and Sora for display. The app loads Montserrat for everything and keeps Sora only for the wordmark (ui/src/app/layout.tsx). Montserrat is wide and dark at 13 to 14 px, so nav rows and table cells feel heavier than the kit intends.

Change. DM Sans 400/500/600 for interface, Sora 600 for page titles, big numbers and the wordmark, JetBrains Mono for ids, timers, numbers and keys. One font swap in layout.tsx and the tokens in globals.css.

Two accents fight for "primary"

HIGH

Now. Brand green is the button colour, but the active nav row, focus rings, selection, the avatar chip and the sidebar "primary" are all sky blue (globals.css: --sidebar-primary, --ring; AppSidebar.tsx: bg-sky-dim text-sky). Nothing in the kit is blue, so the UI reads as a generic shadcn app with a green button.

Change. Green is the one interactive accent: primary buttons, active nav, focus ring, selected rows, links. Sky stays as an information tone only (pills, "viewing version"). Spark orange is reserved for live calls, as the kit says.

207 hard-coded palette colours

HIGH

Now. 54 component files still use Tailwind's raw palette (text-red-500 on the create page error, text-green-600 on the success dialog, grey and blue variants in filters, tools, billing, telephony). These ignore the tokens, so they look wrong in one of the two themes and never match the brand greens.

Change. Map each to a token (danger, ok, sky, amber, ink-3) and add an ESLint rule that bans raw palette classes so it cannot regress.

Five corner radii, three button heights

MEDIUM

Now. Panels 10 px, cards 10 px, buttons 8 px, nav rows and header buttons 7 px, pills 6 px, the tester 12 px, dialogs 12 px. Buttons are 36 px in the body, forced to 28 px when portalled into the header (.page-actions in globals.css), and the kit asks for 44 px.

Change. Four radii: 6 chip, 8 control, 12 card, 14 shell panel. Three button heights: 32 toolbar and table, 36 default, 40 form CTA. Drop the un-layered header override and let the slot pick size="sm".

Two card looks, plus a texture

MEDIUM

Now. The Card primitive paints a 45° crosshatch, a shadow and (dark only) a bright top edge; inside the content panel a second rule flattens it to panel-2 with no shadow. So the same component looks raised in a dialog and recessed on a page.

Change. One flat card everywhere: panel surface, 1 px hairline, 12 px radius, no texture. Elevation (shadow) only for things that float: menus, popovers, dialogs, the floating canvas toolbar.

Dark is a different brand from light

MEDIUM

Now. Light surfaces carry a faint green cast (#F3F6F4 on #0B2E22 ink). Dark drops to neutral blue-grey charcoal (#0B0D11, ink #F1F3F6), so switching themes changes the personality, not just the brightness. Dark is also force-locked as default (enableSystem false) while the kit says light default, system aware.

Change. Use the Uncava dark ladder from app-lightmove (#08090B, panel #0E1013, ink #F4F6F8) with Mint as the only colour, and follow the OS by default with the explicit choice remembered.

B · Voice agents landing and create flow

"Workflow" and "Agent" in the same screen

HIGH

Now. Nav says Voice agents, the button says Create Agent, the empty state says "No active workflows found", toasts say "Workflow archived", a blank agent is named "Workflow-x7k2", the success dialog says "Workflow Created Successfully!" (WorkflowTable.tsx, CreateWorkflowButton.tsx, create/page.tsx).

Change. "Agent" is the only word users see. Default name "Untitled agent". Sentence case everywhere (Create agent, Active agents).

A table that hides what matters

HIGH

Now. Columns are ID, name, created date, total runs, and three bordered buttons per row (Edit, Move, Archive). The row already opens the agent, so Edit is redundant, and the numeric ID is the first thing you read. There is no status, no channel, no last call, no search.

Change. Row = mark + name + draft/published pill, channels (phone, web), runs with a 7-day sparkline, last call, one kebab menu (Open, Duplicate, Move, Archive). Search and a status filter above; a stat strip (agents, calls today, minutes, success rate) so the landing answers "how is it going".

Creating an agent takes four screens

HIGH

Now. Create Agent opens a dropdown (Agent Builder or Blank Canvas); Builder navigates to a page with a generic "Agent Details" card, a full-screen loading overlay, then a success dialog with three paragraphs, then the editor. Templates (TemplateCard.tsx) are not reachable from here at all.

Change. One dialog with three ways in (Describe it, Start from a template, Blank), the form inline for Describe, generation shown as a progress state inside the dialog, then straight into the editor with the test rail open.

C · Inside the agent: Conversation editor and Advanced settings

Editor state is split across two bars

HIGH

Now. Save, Publish and Phone call are portalled into the 46 px app header next to the breadcrumb; Rename, version, "Unsaved changes" and errors sit in a second 48 px toolbar below (WorkflowEditorHeader.tsx). The thing you are saving and the Save button are 60 px apart in different bars. The agent name is printed three times (header, nav, rename button).

Change. One editor toolbar: name (click to rename) + version pill + unsaved dot on the left, Phone call / Save / Publish / more on the right. The app header keeps only workspace identity.

Canvas controls scattered in corners

MEDIUM

Now. Add node is a lone green round button top-right; zoom in, zoom out, fit and tidy are four square buttons at bottom-12 left-8 (RenderWorkflow.tsx); the add-node sheet slides over the whole viewport in bg-background with a 20 px title.

Change. One floating toolbar at the bottom centre: Add node (primary), then zoom out, 75 %, zoom in, fit, tidy. Node palette opens as a panel inside the canvas column, not over the test rail.

Test rail has no state of its own

MEDIUM

Now. Two grey tabs (Audio, Text), a close X that does nothing on desktop, then a nested 12 px rounded box inside the 10 px panel. Nothing says whether a call is live, how long, or which node the agent is on.

Change. Rail header: "Test agent" + a live pill (spark orange dot, timer) + segmented Voice / Text. Transcript with node-transition markers. A composer pinned to the bottom. Same rail on every agent screen, as today.

Settings: 1,500 lines, seven Save buttons

HIGH

Now. Seven stacked cards (General, Variables, Dictionary, Voicemail, Identity, Recordings, Report), each with its own footer Save. General alone holds nine sub-sections as 14 px h3s. There is no way to jump to a section and no indication of what is unsaved.

Change. Sticky section index on the left, one card per section with the same header (icon, title, one-line description), each setting as a row (label + help on the left, control on the right), and a single sticky save bar that appears only when something changed.

Agent nav: three groups for five rows

LOW

Now. CONFIGURE (3), CONNECT (1), ANALYSE (1). The labels cost more height than they organise, and the status pill under the agent name is a one-off style instead of StatusPill.

Change. Keep the groups (they will fill out), but tighten to 12 px label spacing, use StatusPill for the version status, and show a count on Runs.

Header: mono and sans breadcrumb

LOW

Now. The workspace switcher is mono, the page title is sans semibold, the strapline is mono again and only shows above 1280 px. Overview is the one page that also prints an h1 in its body.

Change. Breadcrumb entirely in DM Sans (workspace in ink-3, page in ink), mono reserved for data. Straplines move into the page as a one-line description under a compact page title, so every screen has the same opening.

Design principles for the redesign

  1. One accent. Green does every interactive job. Blue, amber, red, orange are statuses, never buttons.
  2. Same opening on every screen. Title, one-line description, actions on the right, then content. Nothing repeated in the header.
  3. Flat surfaces, floating overlays. Shadows only on things that are above the page.
  4. Rows, not button rows. A list row navigates; secondary actions live in one menu.
  5. Dark uses the Uncava ladder. Cool near-black surfaces in steps, same spacing and type; Mint is the only colour.
  6. Voice is the product. Live state uses the spark orange and a waveform, everywhere a call is happening.

Suggested order of work

  1. Tokens and type in globals.css and layout.tsx: fonts, Uncava dark, near-black light ink, green ring and active nav, radius scale, flat Card. Reaches every screen at once.
  2. Copy pass: agent everywhere, sentence case, default names.
  3. Voice agents landing: new row model, search, filter, stat strip, empty state, create dialog.
  4. Editor toolbar and canvas toolbar, then the test rail header.
  5. Advanced settings: section index, setting rows, single save bar.
  6. Palette lint rule and migration of the 54 files.
