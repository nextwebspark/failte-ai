## How it works

**Models & voice** sets how every agent in your workspace talks. Fallcha.ai runs the models for you on Google Cloud in the EU, so there are no provider accounts or API keys to manage.

Open **Models & voice** in your Fallcha.ai dashboard (`/model-configurations`). You make two choices:

1. **How should your agent talk?** Speech-to-Speech, or Speech-to-Text → LLM → Text-to-Speech.
2. **The models, voice and language** for that choice.

Save, then publish your agents to use the new settings on calls.

<Note>
Settings apply to the whole workspace. A single agent can use different ones, see [Per-agent voice and model](#per-agent-voice-and-model).
</Note>

## Speech-to-Speech (recommended)

One model listens and speaks directly, with Gemini Live. Conversations feel the most natural and have the lowest latency.

| Setting | What it controls |
|---------|------------------|
| **Model** | The speech-to-speech model. |
| **Language** | The language the agent speaks and listens in. |
| **Voice** | One of the Gemini Live voices. Play a sample next to each voice before choosing. |

Choose this for most agents.

## Speech-to-Text → LLM → Text-to-Speech

Three separate steps: a transcriber turns the caller's speech into text, a language model writes the reply, and a voice speaks it. Choose this when you need a specific voice or language that speech-to-speech doesn't offer, or finer control over each step.

| Step | Settings |
|------|----------|
| **Speech-to-text** | Model (Chirp 3, Latest long or Latest short) and the caller's language. Each model lists the languages it supports. |
| **Language model** | Gemini model and temperature. Lower temperatures give more predictable replies; leave it blank for the model default. |
| **Text-to-speech** | Voice language, voice (Chirp 3 HD, with samples you can play) and speaking speed. |

When you change the voice language, Fallcha.ai keeps the same voice in the new language where it exists. Otherwise pick a voice for that language.

## Per-agent voice and model

An agent can use a different mode, voice or model than the workspace:

1. Open the agent and go to **Model and voice**.
2. Turn on **Use a different voice or model for this agent**.
3. Choose the settings and click **Save agent voice & model**.
4. Publish the agent.

To go back to the workspace settings, turn the switch off and click **Use workspace default**, then publish.

<Note>
If Fallcha.ai support manages your workspace's model settings (for example on an Enterprise plan), the page is read-only. Contact support to change them.
</Note>

## Self-hosted deployments with your own providers

Self-hosted deployments that don't run platform-managed models configure providers and keys instead.

On those deployments the Models page has three top-level sections:

| Section | When to use it |
|---------|----------------|
| **Speech to Speech** | Use a realtime speech-to-speech model for the live conversation. You still configure an LLM alongside it for variable extraction and QA. |
| **Fallcha.ai** | Use Fallcha.ai-managed LLM, voice, and transcriber models behind one Fallcha.ai Service Key. |
| **BYOK** | Bring your own provider keys and configure LLM, Voice, Transcriber, and Embedding models separately. |

<Note>
Model settings are organization-scoped. If no agent-level override is set, every agent in the organization uses the saved global configuration.
</Note>

## Speech to Speech

Use **Speech to Speech** when you want a realtime model to handle the live spoken conversation directly. In this mode, the realtime model handles speech input and speech output, so you do not configure separate Voice and Transcriber services.

![Speech to Speech model configuration](../images/model-configuration-speech-to-speech.png)

The Speech to Speech section has nested tabs:

| Tab | What to configure |
|-----|-------------------|
| **Realtime Model** | The speech-to-speech provider, model, voice, and API key. |
| **LLM** | A standard LLM used for non-realtime tasks such as variable extraction and QA analysis. |
| **Embedding** | An embedding model used by features that need embeddings, such as retrieval from knowledge base content. |

<Warning>
An LLM is still required when you use Speech to Speech. The realtime model handles the live voice conversation, but Fallcha.ai uses the LLM for analysis tasks that happen outside the live audio stream.
</Warning>

## Fallcha.ai

Use **Fallcha.ai** when you want Fallcha.ai to manage the model providers for you. This path uses one Fallcha.ai Service Key for Fallcha.ai-managed models instead of separate provider keys for LLM, Voice, and Transcriber.

![Fallcha.ai model configuration](../images/model-configuration-dograh.png)

Configure:

| Field | What it controls |
|-------|------------------|
| **Voice** | The Fallcha.ai-managed voice to use. |
| **Speed** | The voice playback speed. |
| **Language** | The language behavior, including multilingual auto-detect when available. |
| **API Key** | Your Fallcha.ai Service Key. Create Service Keys from **Developers**. |

For details on creating and using Service Keys, see [API Keys and Service Keys](api-keys#service-keys).

## BYOK

Use **BYOK** when you want to bring your own provider accounts and API keys. This gives you separate control over each model category.

<Warning>
When you use BYOK or external model providers, Fallcha.ai sends only the data required for the selected service to operate. Depending on the provider and service type, this may include prompts, conversation history, transcripts, audio, generated text, tool/function definitions, tool inputs or results, and request metadata.

Provider data handling varies. Review each provider's data processing, retention, model training, and regional hosting policies before using sensitive data.
</Warning>

![BYOK model configuration](../images/model-configuration-byok.png)

The BYOK section has nested tabs:

| Tab | What to configure |
|-----|-------------------|
| **LLM** | The chat or reasoning model provider, model, optional base URL, and API key. |
| **Voice** | The text-to-speech provider, voice, model, speed, optional base URL, and API key. |
| **Transcriber** | The speech-to-text provider, model, language, and API key. |
| **Embedding** | The embedding provider, model, and API key. |

Provider-specific fields appear only when they apply. For example, OpenAI-compatible LLM providers can expose a **Base URL** field, ElevenLabs voices can expose a voice ID, and transcribers can expose language options.

### Agent-level model overrides (own providers)

You can override the organization model configuration for an individual agent. This is useful when different agents need different models, voices, transcribers, or providers.

To configure an override:

1. Open the agent.
2. Go to **Settings**.
3. Open **Model Overrides**.
4. Enable the override for the service you want to customize.
5. Configure the provider, model, and keys for that service.
6. Save the agent settings.

Agent-level overrides are selective. For example, you can override only the Voice service for one agent while it continues to use the organization-level LLM and Transcriber configuration.
